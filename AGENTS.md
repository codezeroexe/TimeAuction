# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

TimeAuction: competition web app (React 19 + TypeScript + Vite + Tailwind v4) plus a zero-dependency Node event server. See `README.md` for the participant flow and honest limits.

## Commands
```
npm run dev        # Vite on :5173, proxies /api to :8787 if the event server runs
npm run server     # event server only (:8787), Node runs .ts directly (no build step)
npm run event      # build, then serve app + API on :8787 (live event)
npm run build      # tsc -b && vite build
npm run lint       # oxlint
npm test           # node --test over src/**/*.test.ts and server/**/*.test.ts
npm run loadtest   # 34 simulated stations (2×12, 1×6, 2×2) vs a real server
npm run seed:match -- 12  # dev: register and pair N players on a running server (BASE, default localhost:8787)
```
Single test file: `node --test src/game/auction.test.ts` (add `--test-name-pattern="..."` for one case).
Admin PIN: `TIMEAUCTION_ADMIN_PIN=123456 npm run event` (PowerShell: `$env:TIMEAUCTION_ADMIN_PIN="123456"; npm run event`), otherwise generated and printed on start. Event PCs run Windows: `start-event.bat` is the host launcher; show shortcuts as Ctrl, not Cmd.

## Architecture
- **Two runtime modes, one reducer.** `src/game/actions.ts` is the single reducer used by both the browser (single-device, `localStorage` key `timeauction:game`, schema v6) and the server (`server/host.ts`, authoritative). `src/state/` has the two providers (local / remote); the mode is picked at page load by probing the server.
- `src/game/` is pure, tested logic with no React or Node imports: auction engine with hash-chained event log (`auction.ts`), `bot.ts`, `rules.ts`, `scoring.ts`, `leaderboard.ts`, `integrity.ts`. Keep it pure so the server can import it.
- `server/host.ts`: authoritative state, idempotent requests, per-side claims (`sessionId → side → clientId`, one station per side), station keys (`gameId.HMAC`, secret in `event-data/server-secret`; returned by register/resume, sent as `key` on actions and `/api/stream`; a Game ID alone grants nothing; judge `issueResumeCode` gives a single-use 10-minute code for moving PCs), per-IP registration limit (`TIMEAUCTION_REGS_PER_IP`, default 0 = off because event PCs are shared, loopback exempt), server clock, per-subscriber views (participants see only their own records, with no side Game IDs, and before the twist reveal `twistId ''`, `runId 'SEALED'`, pending lots `techId ''` via `forPlayer`; admins see all, throttled to 1/s unless the SSE has `live=1`). Payload `offline` lists human sides with no connected station; a disconnect never pauses a match, a server restart does. `server/index.ts`: HTTP + Server-Sent Events + static serving of `dist/`.
- Auth (`server/auth.ts`): judge accounts (salted scrypt, `judges.json`) plus superadmin user `admin` with the PIN; session cookie `ta_sid` (HttpOnly, SameSite=Strict, Path=/api), in memory, so a restart signs everyone out. Login lockout per IP and per username (loopback exempt). Any request carrying a judge session gets 403 on bid/pass; `resetEvent`/`updateSettings`/judge management are superadmin-only.
- `#/present` (`src/screens/present/`): projector, judge sign-in required. Stages (Welcome, Rules, How to join, Teams, Matchups, Auction, Twist, Results; order in `SHOW_STAGES`) come from `EventState.show` (`setShow`, judge-only, not audited); the screen has no controls and hides the cursor. `#/present/preview` is the console thumbnail (silent); `#/present/<sessionId>` names a room big. `#/auctioneer` redirects here. The Welcome stage (`Welcome` in `stages.tsx`, `.welcome-*` in `index.css`) is title left, a planet right with eras orbiting it on tilted SVG `animateMotion` paths (labels stay upright, drawn over the planet), plus aurora, drifting dust and `ShootingStars`; it no longer uses the landing `Chronometer`.
- Host console: `src/screens/admin/Show.tsx` (Admin → Show control, rooms with Start auction / Pause / Resume / Next technology / Reveal twist / Show on projector) and the stage bar `ShowBar.tsx` on every admin page (Ctrl+←/→). Only the console and the projector drive lots and reveals; players cannot.
- Held matches: `pairMatch{hold}` leaves a server-paired match `ready` until a judge's `proceedToAuction`; players get 403. `proceedToAuction` also sets the projector to the Auction stage focused on that room. Show control lists only rooms still in play (held, live, or finished with a twist reveal pending). Server-paired runs have `twistHeld`: `continueToMission` waits for a judge's `revealTwist`. The gate only synchronises the reveal (see README honest limits), it is not secrecy.
- Server persistence: `event-data/` (`event.json`, `claims.json`, `keys.json` (retired station-key versions), `admin-pin`, `server-secret`, `judges.json`), atomic writes coalesced every 200 ms. Unreadable file means the server refuses to start rather than overwrite. Vite ignores this dir for reloads; don't commit or hand-edit it.
- `src/screens/` participant UI; `src/screens/admin/` admin + scoring panel at `#/admin` (hash routes in `src/state/`).
- `#/idle` (`src/screens/Idle.tsx`, `idle.css`): attract loop for an unattended station, opened from the Ctrl+K palette ("Idle screen"). Full-screen, no Credit header, palette or toasts; starfield, `ShootingStars`, two counter-rotating era rings (labels counter-spin to stay upright), floating CC coins, rotating taglines, a small static "Press any key to start". Any key or click goes to the landing page. Player stations also fall back to it by themselves: `AfterMatchIdle` in `App.tsx` calls `leaveStation` (freeing the PC for the next registration; records stay) and sends a remote, non-judge station to `#/idle` after 60 s without input once `stationDone` (`src/game/solution.ts`) says the match is over for every side it plays (submitted, timed out, or too few technologies). The projector Teams slide lists only lobby players with a connected station (admin payload `online`), and Show control has a Clear lobby button plus an "On the Teams slide" list with Hide per player (`hideFromLobby`, audited, sets `Participant.lobbyHiddenAt`; Admin → Participants "Return to lobby" undoes it).
- Fit to window: game screens pass `fit` to `GameShell` (Lobby, MatchSetup, Auction, Summary, Twist, Mission, Solution, Results). `useFit` scales the content with CSS `zoom` (Chromium) to fit below the Credit header, never below 0.72; past that the main column scrolls. Fit screens hide the GameShell footer. Long reading pages (landing, rules, leaderboard, admin) leave `fit` off and use `.page-shell`, which fills the window under the header without overflowing it. Keep new game screens compact enough to fit 1080p at zoom 1.
- Landing page ends at the scoring section: the closing CTA and footer were removed, so `#/admin` is reached through Ctrl+K or the URL.
- N sides: a match has 2 to 12 sides. `SideId` is a string (A…L, `SIDE_IDS`); always enumerate with `sidesOf(session)` from `auction.ts`, never hard-code A/B. `MIN_SIDES`/`MAX_SIDES` live there too. No new bot matches: `pairMatch` and `createMatch` reject a bot opponent (ChronoBot, `bot.ts` and 'ivbot'/'tvbot' stay only so saved runs still load).
- `src/game/draw.ts`: pure seeded draws from the run ID: `lotCount`/`shortLotCount`, `lotsForRun` (picks the twist first: most lots move under it, 1–3 off-theme “Wildcard” lots), `wildcardForRun` (half-price “Bargain lot”), `matchRuleset` (lots, starting wallet `walletFor(lots)` = max(1000, 200 per lot) in `rules.ts`, clock, `offThemeTechIds`, bargain lot for one match). Server and browser agree because both call it.
- One match at a time: `pairMatch` returns 409 while `activeMatch(ev)` (a session `ready` or `live`) exists; `concurrentMatches: true` on `startServer`/`createHost` is for stress tests only.
- Remote matchmaking: judges pair 2–12 waiting registrations (`pairMatch{gameIds, hold}`, admin Matchmaking tab; hold is on by default in the console); every non-first station joins its own side via the `paired` payload field and `joinSession`, and players cannot start or replay matches.
- Content: 50 technologies (`src/data/technologies.ts`, each with `tags`) and 30 twists (`src/data/scenario.ts`). Twist = `twistForRun(runId)`; tool values come from `valuesFor(twist)` (per-tag deltas, per-tech `overrides` win) scaled by `twistStrength(runId)` (mild/normal/severe). Values are display only for the bot, but each selected technology adds `round(delta/10)` points (half away from zero, -5..+5) to the final score: rubric 0-100 plus tool points (`toolPoints`/`finalScore` in `src/game/scoring.ts`). Judges' per-criterion notes are no longer entered or shown (`note` stays in the type and storage).
- Solution rules: at least `solutionTechCount` (now 1 in both rulesets) distinct acquired technologies with no upper limit, 1–`MAX_CHARACTERISTICS` characteristics, `SOLUTION_WORDS`: at least 40 words, 60 is only a suggestion (never blocks), `solutionSeconds` 300 when timed; when the clock runs out the server (`autoSubmitDue` in `tickAll`) locks the draft as written via `autoSubmit` after `DRAFT_GRACE_MS` (3 s, during which the last draft save still lands), marked `Submission.auto` and exempt from the minimums (`src/game/rules.ts`, checked by `checkSolution` in `solution.ts` and `integrity.ts`). Saved runs keep the counts they snapshotted.
- Lot clock: the engine (`tick`) runs each lot through intro (`Lot.phase` 'intro', `introSeconds`) → bidding ('open') → result pause ('decided', `nextLotSeconds`) → next lot; the server ticks it. Players cannot start/pause/advance lots (403); only a judge session can. Single-device mode keeps the buttons.
- Event PCs reach the server over plain HTTP on a LAN IP (not a secure context): no `crypto.randomUUID` (use `randomHex`/`makeId` in `src/game/ids.ts`) and no bare `navigator.clipboard` (use `copyText` in `src/components/ui/toast.tsx`). Saves go through `replaceFile` in `server/index.ts`, which retries renames that Windows antivirus/indexing locks (EPERM) and never crashes the server.
- UI follows the v6 design system in `src/index.css` (`.pn`, `.pn-hot`, `.lbl`, `.chip`, `.btn`, frosted `.credit` strips) and motion helpers in `src/components/ui/motion.ts` (`calm`, `countUp`; respect reduced motion). Desktop 1080p only, no mobile.
- Changing game state shape: bump the storage schema and keep corruption detection in `src/state/` storage working. Current: schema v6 (`EventState.show` added; v3–v5 load by version bump with the default show; `src/state/storage.ts`).

## Delegation (always on, no need to ask)
Delegate work to the project subagents in `.Codex/agents/` automatically:
- **planner** (Opus): before any non-trivial feature, redesign, or task with an unclear approach. Get a plan first.
- **worker** (Haiku): to execute decided steps - edits from a plan, mechanical changes, running build/tests/lint.
- **auditor** (Sonnet): after code changes and before an event, to review the result. Fix what it confirms (via worker), then re-check once.

Typical flow: planner -> worker -> auditor. Handle trivial one-line answers or tiny edits directly.
Pass each agent full context in its prompt (files, goal, constraints) - they start with no memory of the conversation.
Relay results honestly; agents' reports are not shown to the user.
